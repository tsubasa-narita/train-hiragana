# ひらがな でんしゃ

電車が好きな3歳のお子さん向けに、好きな電車の名前から文字の形と音に親しむ、小さな学習アプリです。

公開URL: https://tsubasa-narita.github.io/train-hiragana/

## あそびかた

- **なぞって はしろう**：清音46文字を指で書くモード。書き順・進む方向に沿って電車が走り、1文字完成すると対応する電車の絵が登場します。お手本、途中再開、行・文字の選択に対応。完成後は自分のペースで次へ進めます。[詳細・字形の出典・検証](docs/tracing.md)。

- **もじをみつけよう**：清音46文字すべてに対応。44文字は実在の列車・路線・鉄道会社の名前や愛称の先頭から出題。「を」「ん」のみ言葉や名前の途中を使います。「ぬ」は昔の沼尻軽便鉄道、「る」は昔の留萌本線です。[46文字の対応表](docs/kana-coverage.md)を参照してください。最初は見本ありの2択です。
- **行をえらぶ**：ホームで「あ・か・さ・た・な・は・ま・や・ら・わ」を複数選択できます。「あ→い→う→え→お」のように五十音順に出題します。1行だけなら毎回行の最初から。や行・わ行は3文字を順番に繰り返して5問です。複数行・「ぜんぶ」は5文字ずつ進み、完走した続きの位置をブラウザに保存します。図鑑から遊ぶと、その電車の行に切り替わって行の最初から始まります。
- **なまえをつなごう**：好きな電車の名前を、音と形のお手本で一文字ずつ連結します。3つの名前を完成させると、ごほうび電車が走ります。タップとドラッグに対応し、こまちは新しい専用画像で実際の車両も一文字ずつ連結します。
- **でんしゃずかん**：205種類の電車・鉄道を最初から自由に閲覧。遊んだ電車にスタンプが付きます。犬の場面では、絵に登場する京急線のスタンプが付きます。名前の各文字も読み上げます。
- **あいうえお**：清音46文字、濁音、半濁音、小さい文字と長音符をタップして音を聞けます。
- **ごほうび電車**：5問すべて正解して旅を終えると、36種類からランダムな電車が走行音とともに画面を横切ります。車体は全36車種を精密な模型風の右向き側面画像に統一。虹の橋・駅でひとやすみ・星空急行の3種類の景色には、橋脚・水面反射・駅舎・月や街の灯りを描き込んでいます。[ビジュアル仕様と画像生成記録](docs/reward-visual-quality.md)。電車と演出はそれぞれ直前と同じものを避け、「もういっかい はしる」で同じ電車を別の演出で何度でも再生できます。「つづける」で演出中にも先へ進めます。名前の連結では3つの名前を完成させたときだけ登場します。途中の正解はチャイムと文字表示で応援します。端末の「視差効果を減らす」設定では走行の代わりに静止表示します。

1回5駅。回答の制限時間、減点、連続日数の要求はありません。正解を最低1秒見せ、「できたね」の発音が終わってから自動で次の問題や文字へ進みます。5問目も同じ条件で完走画面とごほうびを表示します。待機中の連打は無視し、ホームへ戻った場合などは予約した遷移を取り消します。「いま すすむ」で待たずに進むこともできます。保護者向け設定から、文字見本を隠す3択にも変更できます（電車名は手がかりとして表示）。

## 開発

Node.js 20以上。外部npmパッケージは不要です。

```sh
npm run dev   # http://127.0.0.1:4173
npm test
npm run build # dist/ に静的ファイルを出力
```

ES Modulesを利用するため、index.htmlの直接ダブルクリックではなくHTTPサーバーで開いてください。

## GitHub Pages

ビルド不要のHTML/CSS/JavaScriptで、すべてのアセットは相対パスです。GitHubの Settings → Pages → Build and deployment で **Deploy from a branch / main / (root)** を指定すると公開できます。`.nojekyll` によりJekyll処理を無効にします。GitHub Actionsや秘密情報は不要です。

## 音声・保存・外部接続

- アプリの全2,182台詞をGemini 3.8 Flash-Lite TTS（Kore）で事前生成。同じ車内アナウンス風の声をMP3として同梱し、端末によらず同じ声を再生します。「おうちのかたへ」で試聴できます。
- 一文字の「は」は「ハ」として生成し、助詞の読みとの混同を避けています。小さい文字は「ちいさい、ツ」などと案内します。
- 音声ファイルが利用できない場合はWeb Speech APIに切り替えます。このときの声・発音は端末依存です。効果音はWeb Audio APIで合成します。
- 特にiOSではユーザー操作後に音声が利用可能になります。「もういちど きく」で再生できます。消音・画面移動で案内音声を停止します。
- 進捗・設定はlocalStorage（`train-hiragana-v1`）に保存。破損・使用不可の場合もプレイを継続できます。アカウント登録・広告・解析・アプリ側のデータ収集はありません。
- フォントはGoogle FontsのZen Maru Gothicを使用し、接続不可の場合はシステムの日本語フォントに切り替わります。OSの読み上げエンジンによってはネットワークを利用する場合があります。
- 初期の電車イラストは依頼者の既存プロジェクト `C:\develop\go-home-puzzle\public\images` から再利用。追加のクイズ用24枚・ごほうび用5枚は、既存の絵に合わせて組み込みImageGenで新規生成しました。[画像生成記録](docs/image-generation.md)に保存先とプロンプトをまとめています。ホームの電車は独自のSVGです。既存画像の一般向け再利用ライセンスは付与していません。

### Geminiアナウンスの再生成（開発時のみ）

```powershell
python scripts/generate-voice-batch.py submit --key-file "APIキーを保存したローカルファイルのパス"
python scripts/generate-voice-batch.py collect --key-file "APIキーを保存したローカルファイルのパス"
python scripts/publish-announcements.py
```

`collect` はバッチ完了まで再実行します。ジョブIDを `.tools/voice-batch-jobs.json` に保存し、既存の有効なファイルを再利用します。`publish-announcements.py` は `imageio-ffmpeg` が必要で、全台詞の圧縮・無音検査が成功してから再生用マニフェストを更新します。MP3は24kHz・モノラル・64kbps。音声の前後には短い間を残します。生成原本WAVはローカルだけに保持し、ビルド・Gitには含めません。

同期生成は `python scripts/generate-announcements.py --all --key-file "ローカルファイルのパス"` に対応。環境変数 `GEMINI_API_KEY` も利用できます。キー・音声生成APIはブラウザへ渡しません。[Gemini TTSの公式仕様](https://ai.google.dev/gemini-api/docs/speech-generation)を参照。

生成後は `scripts/audit-announcements.py` の `submit` / `collect` で全音声を認識し、原稿との一致・読み落とし・繰り返しを検査します。認識はGemini 3.8 Flash、音声生成はGemini 3.8 Flash-Lite TTSです。監査は音声と原稿のハッシュを記録し、変更した台詞だけを再検査します。明確な不良は `scripts/repair-announcements.py` の `submit --keys 修復対象.json` / `collect` で作り直し、再圧縮・再監査します。生成・監査ともローカルのジョブ記録から再開でき、保存失敗を理由に有料生成を重複送信しません。

固有名詞の読みは `assets/voice/pronunciation-overrides.json` に保存します。画面の表記を変えず、`node scripts/voice-manifest.mjs` で音声原稿へ反映できます。小さい文字は単文字・問題・ヒントで共通の読み方を使います。

変更の意図と検証方法は[アナウンス音声の改善記録](docs/voice-update-2026.md)を参照してください。

### 旧音声の生成資料

旧音声の生成には[edge-tts](https://github.com/rany2/edge-tts) 7.2.8を利用しています。[日本語音声の一覧](https://learn.microsoft.com/ja-jp/azure/ai-services/speech-service/language-support)も参照してください。通常のビルド・公開・プレイで音声生成サービスを呼び出すことはありません。

```sh
node scripts/voice-manifest.mjs
python -m pip install edge-tts==7.2.8
python scripts/generate-voice.py
```

生成時に送信するのは固定の学習用文言だけです。`assets/voice/lines.json` に画面で使う文言と読み方、音声の設定を記録しています。再生成スクリプトは生成済みファイルを再利用するため、声・読み方を変更した場合は対象MP3を取り除いてから実行してください。

## ファイル構成

「なまえをつなごう」は3問の名前クイズです。文字を選ぶたびに連結し、3つの名前を完成させると従来のごほうび電車が走ります。こまち・横須賀線・山手線・踊り子・はやぶさ・かがやき・埼京線・湘南新宿ライン・南武線に加え、中央線・京浜東北線・総武線・常磐線・京急線・あずさ・ひたち・成田エクスプレス・スカイライナー・ラビューの計19車種には、新しい専用画像による車両連結を用意しました。音声・お手本・ヒント、途中再開、専用車庫に対応しています。行選択と5駅の旅は「もじをみつけよう」の設定です。最後の文字の発音と連結を見終えてから、ボタンで次問・ごほうびに進みます。未収集の専用車種を優先します。詳細は [連結遊びの仕様](docs/connect-play.md) を参照してください。

- `src/app.js`：画面・読み上げ・ゲーム進行
- `src/data.js`：電車データ・問題生成・保存データ検証
- `src/reward.js`：ランダムなごほうび電車、走行演出、走行音、再生・終了管理
- `src/voice.js`：音声ファイル再生・停止・端末音声へのフォールバック
- `src/voice-lines.js`：問題やヒントの読み上げ文言
- `assets/voice/`：生成済み音声と生成用マニフェスト
- `src/style.css`：レスポンシブ表示・動きを減らす設定への対応
- `assets/trains/`：電車イラスト
- `tests/`：問題生成と保存の回帰テスト

電車を増やす場合は `assets/trains/` に画像を配置し、`src/data.js` の `TRAINS` に追加してください。

205種類の電車はそれぞれ専用画像を使用しています。クイズ画像は232枚（233候補）です。清音46文字のすべてに2枚以上の候補があり、各文字の画像を一巡するまで重複しないシャッフル方式で出題します。書籍の公開目次134名称との照合と新規85項目は [書籍対応一覧](docs/book-expansion-coverage.md)、追加したご褒美10種類は [ご褒美の実車確認記録](docs/book-reward-sources.md) を参照してください。公開目次の範囲での対応であり、本の全199種類の写真・形式を網羅したという意味ではありません。首都圏特急8種類の実車照合は [首都圏特急の追加記録](docs/metro-express-2026.md)、前回追加した9種類は [追加したクイズ用電車](docs/quiz-trains-2026.md)、go-home-puzzle から追加した41種類の比較一覧は [go-home-puzzle 対応記録](docs/go-home-train-coverage.md) にまとめています。

## Androidへのインストール・戻る操作

AndroidのChromeで公開URLを開き、ブラウザメニューの「アプリをインストール」（または「ホーム画面に追加」→「インストール」）を選びます。インストール可能な場合は「おうちのかたへ」にもボタンを表示します。standalone表示のPWAとして、専用アイコンからブラウザのアドレスバーなしで起動します。インストールの表示文言や対応はブラウザにより異なります。

Androidの戻る操作・ブラウザの戻る/進むは、画面ごとの履歴に対応しています。電車の詳細→図鑑→ホーム、クイズ→ホーム、クイズから開いた設定→同じ問題、と戻れます。正解後のタイマーは移動時に停止し、同じ問題に戻ったときだけ再開します。問題ごとに履歴は増やさず、完走画面から戻っても正解数を二重に記録しません。ごほうび表示中の戻るは演出を閉じ、アプリのホームで戻ると通常どおりアプリ外へ戻ります。

`manifest.webmanifest` と192/512pxのPNG・maskableアイコンを同梱。`sw.js` はアプリ本体を保存し、閲覧した画像・音声は取得できたものだけ保存します。未閲覧の画像や音声まで完全オフラインで使えるわけではありません。オンラインでは新しいファイルを優先し、サービスワーカー更新で遊んでいる画面を強制再読み込みしません。キャッシュ名・対象パスをアプリ単位に分け、同じGitHub Pagesドメインの別アプリのキャッシュを削除しません。

実装参考：[MDN インストール可能なPWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)、[MDN History API](https://developer.mozilla.org/en-US/docs/Web/API/History_API/Working_with_the_History_API)。

今回の画像追加・検証結果は [バリエーション拡張記録](docs/expansion.md) を参照してください。

専用車両と検証の記録は [車両連結の対応一覧](docs/connect-train-models.md) を参照してください。
