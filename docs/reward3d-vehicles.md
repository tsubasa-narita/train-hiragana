調査・実装日: 2026-11-11。担当範囲は `src/reward3d-trains.js` と本書のみ。Three.js 0.180.0 の core API で造形し、addon・写真テクスチャ・外部モデルを使用しない。

## 公開API・座標規約

```js
import { REWARD_3D_TRAINS, createTrainModel } from './reward3d-trains.js';
const train = createTrainModel(REWARD_3D_TRAINS[0]);
scene.add(train.group);
for (const axle of train.wheels) {
  axle.rotation[axle.userData.spinAxis] = -distanceMetres / axle.userData.radius;
}
// 再生シーン破棄時:
train.dispose();
```

`createTrainModel` はカタログ要素、`{id, ...overrides}`、id文字列を受け付ける。未知idでは `RangeError`。`cars` 上書きは2〜12両に制限する。

返却項目:

- `group: THREE.Group` — 各編成のルート。
- `wheels: THREE.Group[]` — **車輪単体ではなく左右2輪＋車軸を含む車軸Group**。各車4組。全Groupの回転軸は列車座標のZで統一し、`userData.spinAxis='z'`、`userData.radius=.43` を設定。最後尾反転の影響を回転軸へ残さない。
- `length` — `20 + (carCount - 1) * 20.6`。11両226m、10両205.4m、8両164.2m。連結器の微小な張り出しは含まない。
- `front: 0` — 先頭車中心X。鼻先Xではない。
- `frontX: 10.3`、`rearX` — 連結器を含む撮影・フレーミング用の概算端位置。
- `carCount`、`wheelRadius`、`config`。
- `dispose()` — インスタンスGPUバッファ、共有geometry/material、独自Textureを解放する冪等関数。シーンからルートを除去し子を空にする。

`group.userData.carMetadata` に各車の `index`、`centerX`、`green`、`passengerDoorsPerSide` を格納。

座標:

- 1 unit = 1m、先頭 +X。先頭車中心X=0、後続車X=`-20.6*i`。
- railhead Y=.15、車輪軸Y=.58、踏面半径.43。フランジが踏面より.022m張り出すため、形状bboxの最低Yは約.128。
- 台車中心は各車X=±6.8、台車内車軸は中心から±1.05。
- 車体下辺Y=1.15、側面約Z=±1.45、丸みを持つ屋根頂点Y=4.015。手すり等はZ=±1.55付近まで張り出す。
- 冷房装置Y=4.3前後、パンタグラフ集電舟上面Y=5.478前後。
- 高架下地面Y=-6.5などの背景は親シーンで定義する。車両モジュールは地面を生成しない。

## 造形・材質・描画負荷

車体は側面の実開口パネル、丸い肩とクラウンを持つ屋根断面、底部ベベル、丸い前頭部の押し出し形状で構成。窓の背後に閉じた箱を置かず、ゴム枠／金属枠／ガラス、座席、天井の縁、細い室内灯を重ねる。グリーン車には上下2列の窓、内部中間床と2段の座席を持たせている。

前面は独立マスクと窓、厚いシール、ワイパー、短い日本語CanvasTexture、ヘッド／テールライト、手すり、面取りスカート、連結器、ホースを持つ。E235／E233／5050でマスク・色帯・窓分割・灯位置が異なる。5050は銀色の中央棒ではなく、黒い偏心貫通扉を造形する。

台車は軸箱、梁、斜めのリンク、空気ばね、左右車輪、車軸、ハブ、ボルトを持つ。車輪のラテ形状・左右輪・ボルトは1つの共有geometryへ統合。床下箱、ルーバー、冷房グリル、パンタグラフ、車間幌のひだも造形する。

ステンレス、扉、屋根、枠、床下機器、ガラスは `MeshPhysicalMaterial`。金属とガラスの反射には親シーンのPBR環境を利用。窓には独自に生成した空／地平線の薄い反射マップを併用し、外部画像読み込みは不要。ShapeGeometryのUVは0〜1に正規化し、日本語方向幕と反射マップを正しく貼る。Node環境ではCanvasTextureのみ単色DataTextureへ代替し、DOMなしの生成検証を可能にする。

静的部品はgeometry＋material単位で編成全体を `InstancedMesh` 化。車体・扉・枠・ガラス・装置・グリル等は、各車個別の大量Meshにしない。動く32〜44車軸Groupのみ独立Meshを持つ。同一モデル内のgeometry/materialを共有し、別モデルとのGPU資源共有は行わないため、シーン間の破棄が干渉しない。

## 実施した検証

- `node --check src/reward3d-trains.js`。
- 全4形式のDOMなし生成。基本両数・全長・車軸数・Z軸規約・車輪Y・最後尾車輪の回転方向をassert。
- geometry頂点と全instanceMatrixの有限値、グリーン車2両、車輪フランジ最低位置を確認。
- GPUリソースのdisposeイベントを監視し、共有geometry/material/TextureとInstancedMeshバッファの解放、およびdispose二重呼び出しを確認。
- Edge headless実WebGLで4形式の前面斜め／側面をレンダリングし、窓、座席、前面、足回り、屋根を目視確認。方向幕・窓マップのUV修正も反映。
- 最終両数の4形式を順次描画→破棄し、実WebGLのgeometry数が毎回0、Texture数が環境マップ1枚のみへ戻ることを確認。日本語方向幕が実際に読めることも接写で確認。
- 親シーンの `test-results/cinema` 初回統合画像で、高架線上に描画されることを確認。カメラや背景は親側で継続調整。

最終基本編成の生成時規模（カメラでのカリング前、背景なし）:

| id | 車軸Group | 静的InstancedMesh | ルート子数 | 全車両triangle数概算 |

| yokosuka | 44 | 63 | 107 | 262,958 |
| shonan-shinjuku | 40 | 64 | 104 | 240,264 |
| saikyo | 40 | 56 | 96 | 228,236 |
| toyoko | 32 | 61 | 93 | 185,180 |

描画callsはフラスタムカリング、両面／透明材質の処理、影パス、親シーンによって変化する。上表のInstancedMesh数と車軸数はモデル構成そのものの数であり、完成シーンのcallsとは区別する。

## 統合時の最終照合

5050系の側面窓上に初回モデルで入っていた細い赤線は、公式写真の従来標準外観と照合して削除した。赤帯は窓下のみとする。車両メタデータは初期表示でThree.jsを読み込まないよう `reward3d-catalog.js` に分離し、車両モジュールからも再exportする。
