# ご褒美電車のビジュアル

36車種を維持して、右向きの厳密な側面図に統一。既存画像を車両の色・形・特徴の参照として、組み込みの image_gen で精密な3D模型風の透明画像を生成した。実際の運用編成とは別の、ゲーム用の短い編成として表現している。

最終素材は `assets/rewards/sideview/<id>.png`。入力画像と各最終プロンプトを [generation-prompts.json](../assets/rewards/sideview/generation-prompts.json) に記録している。既存の画像は図鑑などのために残している。

`src/reward-model-assets.js` で画像ごとの透明余白を除く表示範囲を定義し、`src/reward-models.js` でCSS背景として表示する。元の画像ピクセルは変更せず、縦横比を維持して車輪の下端を線路に揃える。車体は画像の読み込み完了後に走り出す。読めない場合は同じ車種を描いた側面SVGに切り替え、操作は継続できる。

`src/reward-scene.js` の3景色はSVGで描画する。

- 虹の橋：空、雲、遠景と近景の丘、樹木、水面、橋脚、反射。
- 駅：夕方の色、駅名、時計、窓の灯り、うさぎとくま、街灯。
- 星空：月、星、遠景の街と窓の灯り、水面反射、橋。

通常は水平に走り、走行後は全編成を画面内に展示。スマートフォンの走行中は車体を拡大する。動きを減らす設定では走行せず、全編成を静止表示する。夜景では車体の明るさを軽く調整する。装飾は読み上げ対象から除外し、閉じる・再走行・続ける操作を維持した。

## レビューで改善した点

サブエージェントが画像一覧とPC・スマートフォン画面を確認。最初のレビューで、左右向きとパースの混在、車輪の浮き、スマートフォンでの編成見切れ、車体と背景の品質差を指摘した。

SVGで全車体を統一した試作は、角度を揃えられたが精密さが不足するという再レビューを受け、3D模型風の画像へ変更した。到着後の縮小モーション表示で車輪が20px浮く問題も修正した。失敗時のSVG車体は不透明な塗りにし、背景が透けないようにしている。

画像一覧の再レビューでは、スペーシアXの塗色を[東武の公式デザイン](https://www.tobu.co.jp/spaciax/fun/)に合わせた白へ修正し、さくらの大きすぎる屋根機器を[JR九州のN700系写真](https://www.jrkyushu.co.jp/trains/700/)を参照して低い設備へ修正。参照画像に由来する窓の動物も除去し、空席とガラスの反射に統一した。

小画面の夜景では月を画面内へ移し、虹は頂点が切れない位置へ調整。高さの低い画面では背景と余白を縮小し、長い電車名・編成・操作ボタンをスクロールせずに表示する。背景の縮尺が変わっても、車輪と線路の位置は同じ基準で計算する。

最終の独立レビューで、全36車種、3景色、PC・スマートフォン・高さの低い画面について、追加の有意義な指摘がないことを確認した。

## 検証

`tests/reward-models.test.mjs` で全36車種の素材・表示範囲・代替SVGを確認。`tests/reward-visual-browser.cjs` で36車種、3景色とPC・375px・320pxの構図、667×375・375×375の低い画面、長い名前、全編成表示、接地、動き軽減、再走行、Escape、画像失敗時の代替表示を確認する。既存の3問ご褒美・5問ご褒美・音声・図鑑の検証も維持する。
